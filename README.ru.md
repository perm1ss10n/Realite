# 🧩 Realite — Minecraft RPG Platform

**Realite** — модульная RPG‑платформа для Minecraft (**Paper**), построенная как набор
взаимосвязанных плагинов, объединённых общим ядром (**RealiteCore**).

Проект ориентирован на:

- долгосрочный прогресс игроков
- глубокие RPG‑системы (классы, эволюции, экономика, города, гильдии, квесты, предметы, магия)
- масштабируемость без бесконечных переписок
- чистую архитектуру и удобство разработки
- монорепозиторий (все модули развиваются и версионируются вместе)

---

## 🧠 Архитектура проекта

```
Realite/
├── RealiteCore/                        # Ядро платформы (API / сервисы / мосты)
└── plugins/
    ├── RealiteClasses/                 # Классы, эволюции, мастерство (хуки интеграций)
    ├── RealiteChat/                    # Форматирование чата + мост гильдчата
    ├── RealiteGuilds/                  # Гильдии, ранги, прогрессия, бонусы
    ├── RealiteCityInfrastructure/      # Города, участки, магазины, рынок, правила регионов
    ├── RealiteQuests/                  # Движок квестов + контент‑паки
    ├── RealiteItems/                   # Кастомные предметы + Items API/Bridge
    └── RealiteMagic/                   # Магия: касты, школы, реагенты, HUD
```

### 🔑 Ключевая идея

- **RealiteCore** — единый источник правды (API, общие сервисы, контракты мостов)
- модули **не должны** зависеть друг от друга напрямую
- интеграции делаются через **bridges/interfaces**, предоставляемые Core (или API модуля)
- модули можно добавлять/убирать и развивать независимо

## ✨ Что уже есть в геймплее

> Realite развивается поэтапно — цель: целостная расширяемая RPG‑экосистема, а не набор разрозненных плагинов.

### 🧬 Классы и прогресс (RealiteClasses)
- выбор класса через GUI
- XP/уровни и правила прогрессии
- эволюции / ветвления
- модификаторы мастерства и баланс‑хуки
- интеграции под магию, предметы, квесты, гильдии

### 🎒 Кастомные предметы (RealiteItems)
Централизованный провайдер предметов для всей платформы.

- YAML‑реестр предметов (стабильные itemId)
- поддержка:
  - `material`
  - `customModelData`
  - ключи локализации для названия и лора
  - glow
  - unstackable предметы
- строгая идентификация (серверная, не «по имени в чате»)
- публичная интеграция через `ItemsBridge`

### 🔮 Магия и спеллы (RealiteMagic)
Система магии, рассчитанная на расширение и баланс.

- реестр спеллов (YAML‑описания)
- проверки каста:
  - права
  - кд (глобальное + на спелл)
  - мана‑стоимость
  - посох/фокус (опционально)
  - реагенты (опционально)
  - стоимость в экономике (опционально)
  - региональные правила (запрет/разрешение + модификаторы)
- таргетинг и доставка:
  - self / entity / block / location
  - instant, AOE, chain (в зависимости от спелла)
- пайплайн эффектов (реестр executors)
  - эффекты подключаемые по типу (например particles/knockback/potions/etc.)
- HUD‑фидбек успех/фейл + диагностика (логирование кастов)
- безопасные smoke‑tests (опционально, для дебага)
- GUI выбора спеллов и требования фокуса
- Интеграции: Classes, Items, Economy, Regions, Guilds

### 🏰 Города, гильдии, квесты
- **Гильдии**: ранги, прогрессия и хуки под бонусы
- **Городская инфраструктура**: заготовки под участки/магазины/рынок + правила регионов
- **Квесты**: движок квестов + контент‑паки и интеграционные хуки

## 🛠️ Сборка и разработка

### Требования
- Java **21**
- Gradle Wrapper (`./gradlew`)

### Сборка
```bash
./gradlew clean build
```
> Проверено на Java 21 и Paper 1.21.x

### Локальный запуск (Paper)
- собери нужные модули
- скопируй `.jar` в папку Paper `plugins/`
- запусти сервер, затем настрой модули в `plugins/<ModuleName>/`

## 🧭 Правила репозитория

- соблюдаем границы модулей (без прямых жёстких зависимостей между геймплей‑плагинами)
- для текста/сообщений используем **Kyori Adventure** (не legacy‑API)
- конфиги — YAML, в сообщениях используем ключи локализации вместо захардкода
- интеграции — через bridges (ItemsBridge, EconomyBridge, ClassesBridge и т.д.)
